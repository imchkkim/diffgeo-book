## 헷갈리는 낱말 표

평이한 낱말이 ML 용어나 다른 뜻과 부딪히면 독자가 모르는 사이에 힘을 쓴다. 아래 낱말은 책 전체에서 한 뜻으로만 쓴다. 학문에서 특별한 뜻으로 쓰는 낱말은 장마다 첫 등장 때 개념과 짧은 사례를 붙인다(다른 장을 가리키지 않고 그 자리에서 다시 적는다). 새로 부딪히는 낱말을 찾으면 이 표에 먼저 올린다. 찾고 고치는 절차와 원래 지시 원문은 `~/.claude/skills/textbook-plain-words/SKILL.md`.

> 사용자 지시 원문 (2026-09-26): "동역학 책에서 수행했던 혼동될 수 있는 용어 정리를 다른 책들에도 적용해줘." (표는 같은 날 사용자 승인)

## 1. 수식 표기: 색과 기호 표

### 규칙 (사용자 지시 원문)

> 수식을 처음 만나는 독자의 부담을 줄이기 위해, 모든 display 수식은 다음 형식을 따른다. 앞으로 만드는 JSX 인터랙티브 위젯도 같은 기호에 같은 색(아래 hex)을 쓴다.
> 1. 수식 안의 기호만 \textcolor{색}{기호}로 칠한다. 괄호, 연산자, 숫자는 기본 글자색. \color는 뒤따르는 것까지 칠하므로 쓰지 않는다.
> 2. 수식 바로 아래에 기호 표를 latex array로 단다. 기호는 같은 색, 설명은 기본 글자색(\text{}). 문서 표는 글자색을 지원하지 않아 array를 쓴다.
> 3. 핵심 기호는 책 전체에서 아래 색을 고정한다. 색은 글자가 아니라 개념에 배정한다. 같은 글자가 다른 개념이면 다른 색이고, 기호 표에 그 식에서의 뜻을 적는다(예: H가 엔트로피인지 해밀토니안인지).
> 4. 그 절에서만 쓰는 보조 기호(m, g, t, Δt, ε, η, ω, l, σ, 상수 계수 등)는 기본 글자색으로 두고 표에 설명만 적는다.
> 5. 새 핵심 기호가 나오면 이 표에 먼저 색을 배정한 뒤 쓴다.

### 형식 예

```latex
$$\textcolor{#9467bd}{\Gamma}^i_{jk} = \frac{1}{2}\textcolor{#d62728}{g}^{il}\left(\partial_k \textcolor{#d62728}{g}_{lj} + \cdots\right)$$

(display 수식은 `$$` 줄 + 수식 + `$$` 줄. 기호 표는 바로 다음 `$$` 블록.)

$$\begin{array}{ll}
\textcolor{#9467bd}{\Gamma}^i_{jk} & \text{크리스토펠 기호 (좌표 보정값)} \\
\textcolor{#d62728}{g}_{ij} & \text{계량 성분}
\end{array}$$
```

첨자·지수에 색을 넣을 때는 중괄호로 감싼다.

> • 한 문제에서 두 학생은 서로 다른 이유로 틀리거나 한 명만 틀린다.
> • 교정 뒤 일상 비유나 일화 하나. 민준의 비유는 학부생 수준(과제, 보고서, 조교), 서연은 수학 수업에서.

### 인물 이미지 자리 (사용자 지시 원문)

> 캐릭터 이미지는 일단 생략. 나중에 고품질 인물별 감정별 이미지 세트를 제공하겠으니 각자 자리만 만들어놓을 것. 한 인물의 대화 차례에 필요한 경우 한 명의 이미지가 들어가는 식으로

- 표정 그림 원본: 교재 공용 `~/lameproof/shared/characters/` (인물 외형·성격·라벨 규칙은 그 `README.md`, 표정 번호 이름은 `generator.py`). 책 안에 사본을 두지 않고 빌드가 dist 로 복사한다.
- 대화는 `<div class="dialogue">` … `</div>` 안에 쓰고(앞뒤 빈 줄 필수), 한 차례 = 한 문단 `**김민준:** 대사`.
- 이미지가 필요한 차례에만 라벨에 표정 인덱스를 붙인다: `**김민준 〔M04〕:** 대사`. 빌드가 그 차례 왼쪽에 공용 폴더의 `M04.svg` 를 넣고, 파일이 없으면 점선 빈 자리를 그린다.
- 인덱스: 선생님 T, 민준 M, 서연 S + 두 자리 번호. 번호의 뜻은 공용 README 가 가리키는 `generator.py` 의 `EXPRESSIONS` 가 원본.
- 감정이 크게 움직이는 차례에만(한 문제에 1~3개). 깨달음 3단은 장의 큰 전환점에만.

### 장 구성 (절 단위, 2026-09-26~)

**한 절(`##`) = 한 페이지 = 한 개념.** 절 안 순서는 왜? → `### 역사: …` → 사례·장난감 예제(여기서 굵은 용어) → 그림·위젯 → `### ML에서: …` → `### 문제 N — …`. 문제는 그 문제에 필요한 마지막 개념 절의 끝에 둔다. 규칙·사용자 지시 원문은 스킬이 원본이다(여기 복사하지 않음):
- 절 나누기·절 안 순서·보존 규칙: `~/.claude/skills/chapter-section-edit/SKILL.md`
- 문제 배치·시험지 상자·대사 표현: `~/.claude/skills/textbook-exercises/SKILL.md`
- 완성 예시: `01-좌표하나로는지구를담을수없다.md` (2~12장은 아직 옛 틀 「출발 문제 / 패턴 / 정리 / 정의 / 핵심 인물과 일화 / 직접 움직여 보기 / 연습문제와 같이 풀기 / 연결되는 세계들」)

이 책의 방언:
- 장 머리 `## 출발 문제` 는 그대로 둔다(답·새 용어 없이 물음으로 끝냄). 빌드가 장 제목과 함께 첫 개념 페이지 머리에 붙인다.
- 장 끝 `## 자주 하는 실수와 요약`: `### 자주 하는 실수`(표: 실수 | 나온 문제 | 바로잡는 법 — 대화에서 학생이 실제로 틀린 것만) → `### 요약` → `### 연결되는 세계들`(옛 표) → `### 막힌 곳`(이 장 안에서 남는 물음만). 다른 장을 가리키지 않는다(chapter-section-edit 원칙 6).
- 굵은 용어 꼴: `**매니폴드** (국소 평탄 공간 / Locally Flat Space)`.
- 따라 계산해 보기: `<div class="worked">`, 장당 1~2개. 해당 개념 절 안에 둔다.
- 문제 하나(연습문제와 같이 풀기 짝, 사용자 지시: "연습문제와 같이 풀기를 각각 붙여놓자 문제1 - 같이 풀기 세션1, 문제2 - 같이 풀기 세션2 식으로"). 장 전체에서 3~4문제(확인·계산·킬러), 번호는 장 안에서 이어 매긴다. 장의 첫 문제 제목 바로 아래에 소개 한 줄("각 문제를 먼저 혼자 풀어 본 뒤, …").
  ```
  ### 문제 N — 제목
  <div class="exercises"> <span class="level">확인|계산|킬러</span> 문제 </div>
  #### 같이 풀기 세션 N
  <div class="dialogue"> 대화 </div>
  ```
  대화 속 수식도 색 규칙 동일. `.exercises` 는 빌드·CSS 가 흰 바탕 시험지 상자로 그린다(원고는 그대로).
- 모든 수치는 파이썬으로 검증한 뒤 쓴다.
